# 一致性、可用性与性能整改验收（2026-09-27）

本记录对应代码仓库的当前工作区。生产站点未在本轮更新；所有会清表的测试均指向新建、可丢弃的 MySQL/Redis 容器。

| 原问题 | 当前实现 | 验证 |
| --- | --- | --- |
| 跑腿在途上限可由多个 `LOCKED` 任务绕过 | 抢中即占额度；抢单和递补持有同一跑腿事务锁 | `RunnerQuotaIT` 顺序与并发用例 |
| 信用校准覆盖并发事件 | 按分数版本 CAS，冲突后重算；事件与快照同事务 | `CreditCalibrationIT` 确定性交错 |
| 候选先弹出、崩溃后丢失 | Redis 租约领取、到期恢复、旧 token 无法 ACK 新租约 | `CandidateLeaseIT`、用例单测 |
| 缓存删除失败仍记成功 | 删除失败向上报告，延迟消费重试；差异实际修好才标 `fixed` | 缓存适配器、应用与消费端测试 |
| Redis 故障多次超时与启动受阻 | 缓存短时熔断、直接回源；Redisson 懒初始化，WS 订阅后台重试 | 无 Redis 启动测试；JWT 模式下手工 HTTP 发布、详情、抢单 |
| MQ 故障阻断资金事务 | 资金与事件 outbox 同 MySQL 事务，Worker 后续投递 | outbox 事务/重试单测；`FundOutboxWithoutBrokerIT` |
| 单条兜底扫描失败后重试饥饿 | 失败先入持久重试队列再推进游标，重试领取有租约 | 两类扫描与 JDBC 队列测试 |
| 多副本 ID 与 WebSocket 失效 | MySQL 雪花节点租约和时间栅栏；Redis Pub/Sub 分发、30 秒轮询补读 | 租约测试、WebSocket 测试；尚无跨主机演练 |
| 只有常量健康接口 | API/Worker 内部 readiness、调度心跳、Prometheus 业务指标 | 隔离环境启动并读取两个 readiness 与指标端点 |
| 用户账户对账盲区 | 校验最新有序流水的余额与版本是否匹配用户账户快照 | `UserBalanceReconIT`；无流水的初始账户仍需外部开户凭据审计 |
| 流水索引与深页开销 | 增加查询索引；钱包兼容式游标分页和前端加载更多 | 游标边界/JDBC 测试、前端构建、临时表对照 |

全新隔离环境最终执行 `mvn -Dpeergrab.it=true test`：199 项通过，0 失败、0 跳过。`npm run build`、三套 Compose `config --quiet`、前端 Nginx `nginx -t`、迁移 SQL 重复执行和 `git diff --check` 通过。原始压测数据不能直接代表本次修改后的容量；需在相同 8 核环境重新测量完整公网路径、共享/分散钱包负载、1/4 片详情缓存和自然到期 P99。

生产仍使用单 ECS 时，MySQL、Redis、MQ、宿主机均有单点。多主机应用模板只提供代码与编排入口，不替代外部数据服务高可用、备份恢复和负载均衡。上线旧数据库卷前必须停写、备份、执行 `migrate-runtime.sql` 和 `migrate-query-indexes.sql`，随后再部署新镜像；见[部署说明](../docker/ECS_DEPLOY.md)。

S1 另记开闸到请求实际发出的分布；单次尖峰的 `请求数 ÷ 耗时` 不作为稳态 QPS。S4 的 TPS 只用数据库实际完成的结算任务数计算。S5 的延迟从**预定到期时刻**算到数据库持久化状态变更，MQ 正常与扫描兜底分开报告。

## 正确性与消融

| 校验 | 结果与证据文件 |
| --- | --- |
| 抢单名额、抢中记录、Redis/DB 一致性 |  |
| 借贷平衡、账户快照、托管闭环、重复结算 |  |
| 到期流转重复数、卡单数、MQ 积压恢复 |  |
| 数据清理或销毁隔离卷后的状态 |  |

同一消融对只改一个变量，从同一数据快照起跑、预热口径一致，至少重复三轮；报告每轮结果、中位数与波动。S5 的独占 MQ/独占扫描是两种机制对比，需列出两项模式开关。正确性失败的方案直接标记 **FAIL**，不按其峰值吞吐排名。记录发压端 CPU/网络是否先达到瓶颈，并说明公网 10 Mbps 是否影响结果。

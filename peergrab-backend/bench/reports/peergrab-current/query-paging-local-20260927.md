# 本地深分页与索引对照 · 2026-09-27

在隔离的 MySQL 8.0.40 容器中执行 [`compare_deep_page.sql`](../../scripts/compare_deep_page.sql)。脚本只创建会话级临时表，不修改业务表；造数为 100,000 条任务、同一跑腿的 20,000 条跨轮次抢单记录，以及 100,000 条钱包流水（目标用户占 10,000 条）。数字来自单轮 `EXPLAIN ANALYZE` 的实际时间，说明查询计划和量级差异，不代表生产容量或稳定 P99。

| 查询 | 计划中的实际读取 | 本轮耗时 |
| --- | ---: | ---: |
| 广场第 90,001 行，`OFFSET 90000` | 90,020 行索引读取 | 约 102 ms |
| 广场同一位置，`(created_at,id)` 游标 | 20 行索引范围读取 | 约 0.6 ms |
| 钱包首屏，旧索引 | 全表 100,000 行 + 排序 | 约 26.8 ms |
| 钱包首屏，`(user_id,created_at,id)` | 20 行索引读取 | 约 0.5 ms |
| 钱包第 8,001 行，新索引但仍用 `OFFSET 8000` | 8,020 行索引读取 | 约 12.4 ms |
| 钱包同一位置，新索引加游标 | 20 行索引范围读取 | 约 0.3 ms |
| 跑腿历史第 8,001 行，旧 `idx_runner` | 去重 20,000 条、连接 10,000 条任务并排序 | 约 43 ms |
| 跑腿历史，新增覆盖索引 `(runner_id,errand_id)` | 仍连接、排序 10,000 条任务 | 约 27.5 ms |
| 跑腿历史，禁用覆盖索引后复测 | 恢复旧计划 | 约 40.9 ms |

钱包新增索引和游标分别解决了按用户过滤的全表扫描与深页跳过数据。跑腿历史的覆盖索引能缩短去重阶段，但保留了任务回表与排序，不能把它当成深页的完整修复；写入索引成本也尚未测量，因此本轮没有将其加入生产 DDL。

S4 资金写热点的现有 ECS 报告使用共享演示账户；分桶系统账户或每任务托管账户会改变账本账户、对账和历史迁移语义。当前没有跨多轮、真实用户分布的收益证据，本轮保持资金模型不变。隔离栈的 `run_s1_s4_maintenance.py` 现为每档记录 `Innodb_row_lock_waits` 与 `Innodb_row_lock_time` 前后值及增量，字段名明确包含造数阶段。下一轮应对共享账户和独立用户账户分别复测，并结合资金不变量决定是否需要账务模型重构。

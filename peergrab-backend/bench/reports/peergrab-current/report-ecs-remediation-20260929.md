## 本轮实施的修复

- 将详情缓存回填、逻辑过期和 Redis 降级路径纳入 Micrometer 分阶段计时，并保留单飞回填、旧值返回和 DB 真值兜底。
- 对抢单热点增加 `LOCKED` 快速分支和 `GrabPhaseMetrics`，同时保留数据库 CAS 作为最终名额裁决。
- 将详情缓存延迟双删和抢单首轮超时消息改为有界后台投递；发送失败、队列满或停机时保留 `PENDING`，由 Worker 重试和数据库扫描兜底，避免 Broker 故障阻塞已提交请求。
- App 与 Worker 候选配置统一 Redis `500 ms` 超时，并补齐 Broker／Redis 故障、缓存、资金和消息恢复的可审计门禁。
- 自动结算扫描改为单次调度连续处理最多 5 页，并设置 30 秒预算和扫描阶段指标，消除每页之间固定 5 秒的调度空档。
- 结算 owner 查询和钱包账户 `SELECT ... FOR UPDATE` 合并为批量 SQL，减少每笔交易的锁前往返；保留共享 ESCROW/COMMISSION 账户的账务语义和锁顺序。
- Redis 详情重建锁改用 `SET NX PX + token Lua compare-delete`；多分片回填改为原子 Lua；Redis 故障时增加有界 1 秒进程内详情副本，`degradedLocalHits` 单独计数，写入失效先清本地副本。
- 自动结算页内改为单事务批量过账：一次锁定账户、聚合余额和版本、批量更新账户与流水；批失败整体回滚后逐条幂等 fallback。
- 增加详情批量预热接口和 pipeline 写入，预热只读 MySQL 真值并服务展示缓存，不改变资金、抢单和名额路径。
